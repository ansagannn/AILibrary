# QOR — ИИ-библиотекарь: экспериментальная сборка

Это продолжение восстановленного MVP. **Не готово к пилоту или публичному размещению.** Добавлены экспериментальный гибридный поисковый индекс PostgreSQL/pgvector и ИИ-подбор по реальным карточкам. Основной каталог остаётся в SQLite; полная локализация и многие функции ТЗ ещё не реализованы. Доступен также прежний лексический/fuzzy-поиск. `RELEASE_STATUS.md` содержит результаты работ и известные ограничения.

Каталог КАБИС и тестовые базы в архив проекта не включены. В новой базе QOR создаёт 10 демонстрационных записей, не являющихся проверенным каталогом ЖезУ.

## Запуск локально

Требуется Python 3.12+:

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
pip install -r requirements.txt
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

База SQLite создаётся в `data/qor.db`, иной путь задаётся `QOR_DB_PATH`. Существующие записи не перезаписываются, но при старте добавляются новые столбцы и таблицы. **Перед первым запуском новой версии сохраните полную копию старой базы и проверьте её восстановление.** Не запускайте обновление одновременно с другими писателями.

Для управления каталогом сначала создайте локальную учётную запись (команду запускать в той же среде с тем же `QOR_DB_PATH`):

```bash
python -m app.manage_users librarian --role librarian
```

Ввод и подтверждение пароля выполняются скрыто в терминале; минимум 12 символов. Для роли администратора используйте `--role admin`. Роль `librarian` может создавать и редактировать записи, импортировать и экспортировать CSV; `admin` дополнительно имеет доступ к API журнала. Новые сотрудники создаются только этой локальной командой. Обычный просмотр и поиск не требуют входа. В интерфейсе сотрудник может войти и отредактировать карточку.

Пароли хешируются scrypt, токены сессии хранятся на сервере в виде хешей и истекают через 8 часов; клиент хранит токен в sessionStorage. Вход ограничивается по IP только внутри одного процесса. Нет SSO, сброса пароля, полноценной политики доступа, внешнего аудита безопасности и распределённого rate limiting. Обязательно потребуются TLS, защищённое развёртывание и независимая проверка безопасности. Не публикуйте сборку в открытой сети.

## API

- `GET /api/health`, `GET /api/stats`.
- `GET /api/items?limit=50&offset=0&q=...`, `GET /api/items/{id}`, `GET /api/items/{id}/source`.
- `POST /api/search` — `query`, `language` (язык шаблонного ответа), `material_language`, `kind`, `year`, `limit`.
- `POST /api/login` — `username`, `password`; `POST /api/logout`, `GET /api/me`.
- `POST /api/items`, `PUT /api/items/{id}`, `POST /api/import`, `GET /api/export` требуют заголовка `Authorization: Bearer <token>` и роли сотрудника.
- `GET /api/audit` возвращает последние 100 событий и требует `admin`.

Для CSV — UTF-8, обязательный столбец `title`, размер до 10 МиБ. Добавлены поля `isbn`, `udc`, `bbk_candidate`, `availability`, `location`; допустимые значения наличия: пустое, `available`, `unavailable`, `on_request`. Пустое означает «неизвестно». Повторный CSV-импорт создаёт дубликаты. CSV не является полной резервной копией: в нём нет исходных байтов и GUID из КАБИС.

## КАБИС

Проверка и команды в `KABIS_IMPORT.md`. Новые записи получают ISBN из `010^A`, УДК из `675^A` и **предполагаемый** ББК из `621^A`; сопоставление необходимо подтвердить библиотекарю. Поле `899^K` не интерпретируется как наличие. У 133 записей нет `200^A`, они не импортируются автоматически. Наличие и местонахождение можно ввести вручную после проверки. Исходные байты и идентификаторы импортированных записей сохраняются в таблице `kabis_sources`.

Для ранее импортированных записей можно в отдельной копии базы заполнить **только пустые** ISBN/УДК/621 из сохранённых исходных байтов. Сначала сделайте резервную копию и запустите QOR один раз для добавления новых столбцов, затем остановите QOR и все процессы, пишущие в базу:

```bash
python -m app.kabis_backfill --db data/qor.db --report backfill-preview.json
python -m app.kabis_backfill --db data/qor.db --report backfill-result.json --apply --backup before-backfill.db
```

Файлы отчётов и резервной копии должны быть новыми. Операция проверяет хеши исходных записей, делает SQLite backup и выполняет обновление транзакционно; непустые значения не перезаписываются.

## Тестирование и резервные копии

```bash
pip install -r requirements-dev.txt
python -m pytest -q
```

Резервируйте SQLite через SQLite backup API при остановленных писателях; для восстановления остановите приложение, сохраните текущий файл и восстановите копию, учитывая WAL-файлы. Проверка восстановления обязательна. Экспериментальные примеры Docker и Render в репозитории не были проверены в этом окружении и не являются production-инструкцией.

## Гибридный поиск и ИИ

Установка, построение индекса, ограничения и команды приведены в `HYBRID_SEARCH.md`. Построение индекса не выполняется автоматически. SQLite остаётся основной базой; качество поиска и безопасность требуют дальнейшей проверки.

## PDF и электронные ресурсы (прототип)

Кнопка «Изменить / PDF» позволяет сотруднику прикрепить PDF (до 30 МиБ) к записи. Файл открывается непосредственно в браузере по `GET /api/items/{id}/pdf`; загрузка `POST /api/items/{id}/pdf` требует авторизации сотрудника. Если PDF не прикреплён, но в каталоге есть HTTP(S)-ссылка, показывается ссылка на электронный ресурс: она может вести на сайт облака, а не на PDF. Если нет ни того ни другого, интерфейс честно сообщает об отсутствии электронного текста.

Файлы хранятся отдельно от БД в `data/pdfs/` (или `QOR_PDF_DIR`). **Резервная копия должна содержать и SQLite, и весь каталог PDF**; синхронизируйте их при остановленных записях. При замене старые файлы оставляются для восстановления. Проверяются размер, расширение и сигнатура, но не безопасность содержимого. Не размещайте прототип в открытой сети и не загружайте конфиденциальные документы: все прикреплённые файлы доступны без входа. Библиотека должна подтвердить права на распространение каждого файла. Требуются проверка PDF антивирусом и полноценная политика доступа до внедрения.
